# 开发与发布

## 结构

- `src/`：C# / WinForms 源码、系统 csc 构建脚本与 Tests.cs。
- `src/测试样本/`：不含账号或设备资料的回归界面片段与缓存译文。
- `resources/ocr-bundle.json`：已发布资源的固定地址和 SHA-256。
- `tools/prepare.ps1`：获取资源并核对校验值。
- `tools/package.ps1`：从当前源码生成程序、便携 ZIP、完整源码 ZIP 与校验文件。
- `.github/workflows/`：普通提交 / PR 检查及标签发布。

`Tests.cs` 不编入正式 EXE。系统编译器使用 `Microsoft.NET/Framework64/v4.0.30319/csc.exe`。修改后的源码构建为 `src/快译截图.exe`，无需 Python 运行时。

## 获取资源和验证

```powershell
.\tools\prepare.ps1
.\src\build.ps1 -Tests
& .\src\验证.exe
if ($LASTEXITCODE -ne 0) { throw '检查失败' }
.\src\build.ps1
.\tools\privacy-check.ps1
```

默认全部检查需要 Windows 可交互桌面及剪贴板。OCR 子进程只在测试需要时启动。`验证.exe --render-toolbar` 可以离屏生成工具栏布局预览；`--layout-examples` 使用已有样例和缓存译文。`--live-*` 会调用真实 API，CI 不执行。

首次下载后可以离线构建，或从完整源码附件直接构建。`tools/资源准备/` 保留早期资源整理脚本，它们需要按脚本结构手工准备上游文件；普通开发者使用固定校验值的资源下载脚本即可。资源是预编译上游产物，本项目尚未建立所有原生依赖的逐字节可复现构建。

## 发布约定

普通分支和 PR 执行 Windows 检查，无仓库写权限。维护者在 main 检查通过后创建 `v主.次.修订` 标签；标签发布流程再次检查、从准确标签构建并创建草稿 Release。确认附件及说明后将草稿公开，预览版本设置为 Pre-release。

程序集使用四段版本，例如 1.0.0.0 对应标签 v1.0.0。OCR 资源采用独立版本 `ocr-resources-v3`，资源文件不提交至 Git 历史，固定校验在清单中记录。OCR 资源独立发布，应用源码和版本标签分别触发自动检查。

正式附件只有程序 EXE、含说明 / 许可的便携 ZIP、包含 OCR 资源的完整源码 ZIP 和 SHA256SUMS.txt。代码签名尚未提供。源码能构建、自动检查通过、下载校验通过分别是不同结论。

提交采用项目署名；不在提交、日志、附件或说明中写入本机身份。发布后从 GitHub 实际下载附件，重新核对 SHA-256、解包内容和隐私扫描。
